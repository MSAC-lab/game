## 1. M5의 목적

M5는 **객관적으로 일어난 일을, 실제로 알게 된 사람의 경험으로 바꾸고, 그 경험이 이후 판단에 쓰이는 상태를 바꾸는 처리기**다.

완성 후 확인할 최소 사례는 다음과 같다.

1. 도움을 요청한 인물이 실제 응답과 받은 식량을 경험한다.
2. 그 경험을 기억하고, 상대에 대한 믿음·관계·감정이 동결 규칙에 따라 갱신된다.
3. 다음 판단이 그 변경된 상태를 실제 입력으로 사용한다.

다른 사례에서는 한 사람만 절도 시도를 목격하고, 명시적으로 대화한 사람에게만 전언을 전달한다. 듣지 않은 사람은 그 사건 때문에 관계나 평판을 바꾸지 않는다.

‘거절당하면 반드시 도둑이 된다’는 결과는 요구하지 않는다. 변경된 입력이 계산에 반영됐는지를 검증하고, 최종 행동의 방향은 관찰한다. 성격이 같은 사람에게도 경험과 정보가 달라지면 판단 근거가 달라질 수 있어야 한다.

## 2. 기존 계약과 이번 범위

기존 결정 4·5·6·10·14·15·16·17·18·22·23·24를 함께 적용한다. 특히 결정 17의 M5 범위에 이미 들어 있는 **주간 성향 정리와 기억 상한·압축을 이번 마일스톤에서 빼지 않는다.**

| 구분 | M5에 포함 | 이번에 포함하지 않음 |
|---|---|---|
| 사건 | M4의 확정 결과에서 사건 기록 생성, 최소 흔적 상태 보존 | 새로운 절도·전투·재난 판정 |
| 인식 | 본인 경험, A04 당사자의 직접 상호작용, M4가 확정한 A11 목격 | 위치·시야 시뮬레이션, 지각 재판정, 자동 범인 추론 |
| 전달 | 명시적 접촉 목록을 이용한 제한된 1회 전언 처리 | 60명 접촉 일정의 자동 생성, 전 주민 방송, 의도적 거짓말 |
| 변화 | 주관적 믿음, 방향성 관계, 감정, 기억, 성향 변화 압력 | 새 능력치·숙련·성장 체계, 새 성격 축 대량 추가 |
| 시간 | 명시적으로 호출하는 일일 기억·감정 정리와 주간 성향 정리 | 자율적인 하루 전체 행동 scheduler, 장기 자동 플레이 |
| 판단 환류 | 변경된 M3 입력을 새 판단에 연결하고 원인을 추적 | 새 행동군, M3 효용 가중치의 암묵적 변경 |
| 사용자 경험 | 개발용 읽기 전용 관찰 자료 | 플레이 UI, 자연어 심리 엔진, 연애·정치 시스템 |

행동 종류는 M4의 `A00`, `A04`, `A11`을 유지한다. M5 시험의 접촉 목록과 실행 순서는 명시적 test driver가 제공한다. 이를 production scheduler가 완성된 것으로 보고하지 않는다. 전체 마을 데이터·행동군 확장·자동 일정은 후속 M6 범위와 별도로 맞춘다.

## 3. 반드시 분리할 세 층

| 층 | 예 | 읽을 수 있는 곳 |
|---|---|---|
| 객관적 사실 | 한결이 실제로 곡물을 가져갔고 미라만 목격함 | 결과 검증·사건 기록·허용된 인식 투영 |
| 인물별 인식 | 미라는 시도를 봄. 도윤은 미라에게 들음. 다른 주민은 모름 | 해당 소유자의 인식·기억·전달 처리 |
| 해석과 변화 | 같은 일을 보고 규범 위반을 비난하거나 생존 동기를 이해함 | 해당 소유자의 공개된 자기 상태와 이미 가진 믿음을 쓰는 평가기 |

객관적 결과는 인물에게 통째로 복사하지 않는다. 객관적 사건 ID와 해시를 가지고 있다는 사실도 인물에게 모든 내용을 열람할 권한을 주지 않는다. 식별자는 결속·중복 방지를 위한 시스템 메타데이터다.

‘그 말을 들었다’와 ‘그 말을 믿는다’도 다르다. 믿지 않은 전언의 수신 기록은 남길 수 있지만, 그 내용에 근거한 대상의 평판·관계 변화는 적용하지 않는다.

사건을 모른다는 것이 물리적 결과에도 반응하지 못한다는 뜻은 아니다. 가구원이 식량이 늘었다는 자기 가구 상태에 반응하는 것과, 누가 어떤 행동으로 가져왔는지 알아 관계를 바꾸는 것은 다르다. 기존 M3가 허용하는 자기 가구 자원·욕구 입력을 막지 않는다.

## 4. 실행 경계와 원자성

### 4.1 공개 경로의 제안

공개 진입점은 의미상 다음 세 종류로 제한한다. 이름과 exact signature는 결정 26에서 고정한다.

| 경로 | 역할 | 날짜 변경 |
|---|---|---|
| 행동 해소와 사회적 결과 통합 | 검증된 판단 → 기존 M4 해소 → M5 사건·인식·변화 | 없음 |
| 사회적 접촉 처리 | 소유한 인식의 제한된 전언과 수용 | 없음 |
| 하루 종료 처리 | 기존 자원·건강 진행 + M5 기억·감정·주간 정리 | 기존 DayProcessor가 한 번만 수행 |

첫 경로는 M4의 `BatchResolutionRecord`를 실행 중에 직접 받아 사용한다. 외부 caller가 임의로 조립한 outcome·목격 seed·성향 delta를 공개 입력으로 받아들이지 않는다. 내부 소비기는 시험할 수 있지만, 시험용 발행자를 production authority로 취급하지 않는다.

M4는 이미 원본을 변경하지 않고 `next_world`를 반환한다. M5 통합 경로는 이 중간 세계를 보류한 상태에서 사회적 결과를 적용하고, **전체 검증을 통과한 최종 세계만 caller에게 성공으로 반환**한다. M4 내부 결과가 `COMMITTED`여도 M5가 실패하면 상위 통합 작업은 실패이며, 그 중간 세계를 실제 세계로 공개하지 않는다.

구현 시 다음 결속을 검사한다.

- M4 입력 해시와 실제 입력 세계의 일치.
- M4 출력 해시와 반환된 중간 세계의 일치.
- epoch, action ID, outcome hash, seed ID, context ID, 행위자와 목격자 참조의 일치.
- seed가 가리키는 outcome의 실제 포함 여부와 역참조의 일치.
- 필요한 action·결과·관찰 타입이 알려진 허용 목록에 속하는지 여부.
- 최종 객체와 직렬화 데이터의 범위·ID·소유자·역참조·규칙 해시 무결성.

해시는 입력 변조·혼합을 검출하는 결속 수단이지, 임의 외부 입력을 신뢰된 결과로 바꾸는 인증 수단이 아니다.

### 4.2 상태별 처리

| M4 결과 | 사건·경험 처리 |
|---|---|
| batch `REJECTED` | 사회적 commit 없음. 오류 진단을 게임 속 사건으로 만들지 않음 |
| outcome `INVALIDATED` | 행동이 수행되지 않았으므로 거절·목격·비난 경험으로 변환하지 않음 |
| `RESOLVED / A00` | 행동 슬롯·통합 완료는 기록하되 기본적으로 새 사회적 사건·기억·압력 없음 |
| `RESOLVED / A04` | 실제 요청·전달된 응답·최종 지급을 당사자 경험으로 생성 |
| `RESOLVED / A11` | 본인 시도 경험과, 존재하는 목격 seed에 한해 목격 경험 생성 |

모든 outcome이 A00 또는 INVALIDATED여도 통합 완료 표시는 진행한다. 사회적 사건이 0개인 경우와 M5가 누락된 경우를 구분해야 한다.

### 4.3 replay와 순서

`last_integrated_resolution_epoch`와 사회적 처리 revision, 일일 접촉 처리 여부, 마지막 정리 날짜·주차를 명시적 저장 상태로 둔다. 정상적으로 공개되는 세계에서는 M4 해소 epoch와 M5 통합 완료 epoch가 일치해야 한다.

동일한 action이나 사회적 처리 요청을 재적용해 자원·관계·압력을 두 번 받는 것을 금지한다. 새 action 진입 전에는 직전 M4 결과의 M5 통합이 완료돼 있어야 한다.

같은 batch 안의 입력 배열 순서가 달라도 같은 결과가 나와야 한다. 서로 다른 시간·서로 다른 batch로 나눈 실제 사건까지 같은 결과여야 한다는 주장은 하지 않는다. batch 경계와 사건 순서는 저장되는 실행 의미의 일부다.

### 4.4 내부 중간 세계와 최종 세계의 검증 경계 — D26-R01

현재 M4 resolver는 `resolution_epoch`를 증가시킨 다음 `StateValidator.validate_world(next_world)`와 `StateHasher.hash_world(next_world)`를 호출한다. Schema 5에서 4.3절의 epoch 일치를 모든 단계의 동일한 검증 조건으로 적용하면, M5 통합 전의 정상적인 중간 세계도 거부하게 된다.

결정 26은 다음 두 검증 경계를 명시적으로 구분해야 한다.

| 검증 대상 | 결정 26에서 확정할 조건 |
|---|---|
| 신뢰된 통합 경로 내부의 M4 처리 직후 세계 | 해당 M4 결과에 결속된 통합 대기 상태만 허용. 허용 epoch 차이·처리 단계·증거 참조와 구조·자원 무결성 검사를 명시 |
| 최종 공개·저장·재개 가능한 Schema 5 세계 | M4 해소 epoch와 M5 통합 완료 epoch 일치 및 전체 불변식 충족. 미통합 세계의 공개 반환·저장·일반 서비스 입력을 거부 |

검증 API뿐 아니라 중간 세계의 복제·직렬화·해시 계산 경로가 이 경계와 호환되는지도 명세에 포함한다. 내부 artifact를 위한 정규화·해시 계산과 공개 세이브 허용은 구분한다. caller가 검증 완화 옵션을 넘겨 미통합 세계를 일반 입력으로 사용할 수 있는 구조는 허용하지 않는다. 검증 단계의 exact 표현, 함수 signature, 허용 epoch 관계와 오류 우선순위는 아직 미확정이다.

정상 중간 세계의 내부 통과, 같은 세계의 공개·저장 거부, 최종 통합 세계의 통과, M5 실패 시 원본·counter 불변을 하나의 검증 묶음으로 연결한다. 사건이 0개인 A00·INVALIDATED batch도 통합 완료 표시가 필요하다는 기존 계약을 함께 확인한다. 이 항목은 결정 25의 blocker가 아니며, 결정 26 상세 명세의 완료 조건이다.

## 5. 인물에게 허용할 인식

이 절의 표는 **새 M5 투영 정책의 제안**이다. M4의 목격 계산이나 seed 형식 자체를 변경하지 않는다.

| 수신자·조건 | 인식할 수 있는 내용 | 자동으로 주지 않는 내용 |
|---|---|---|
| A04 요청자 | 자신이 요청한 대상·양, 상대가 전달한 응답, 실제 받은 양 | 상대의 실제 총재고·reserve·효용·성향·거절의 숨은 이유 |
| A04 응답자 | 자신이 응답한 요청과 실제 지급한 양 | 요청자 가구의 비공개 상태·속마음 |
| A04 비당사자 | 이 단계에서는 자동 인식 없음 | 현장 인원 목록만으로 요청·응답을 보았다고 가정하지 않음 |
| A11 행위자 | 자신이 한 시도, 목표 창고, 실제 가져간 양 | 누가 자신을 봤는지, 실제 보안 수치, 남은 정확한 재고, 난수 |
| 유효한 A11 목격 seed의 소유자 | 행위자 식별과 절도 시도, 물건을 가져가는 모습의 유무 | 정확한 수량·행위자의 가족 보호 의도·다른 목격자·판정 점수 |
| seed가 없는 인물 | 자동 인식 없음 | 장소에 있었거나 가족·권위자라는 이유만으로 앎 |

최초 M5에서는 유효한 A11 seed를 ‘그 행위자의 시도를 식별해 목격했다’는 입력으로 해석한다. 다시 지각 난수를 굴리거나 지각 점수를 신뢰도로 쓰지 않는다. 관찰 범위를 좁히고, 그 범위 안에서는 오인 없는 직접 경험으로 처리한다. 별도의 오인·얼굴 식별 시스템은 이번 범위가 아니다.

`actual_units == 0`이어도 목격한 절도 **시도**는 남을 수 있다. 반대로 성공했고 목격자가 없어도 행위자 본인은 자기 경험을 가진다. 목격 seed에 `actual_units`나 `trace_created`가 들어 있다는 것만으로 그 필드를 모두 인지했다고 처리하지 않는다.

A04의 `response_decision`을 직접 상호작용에서 전달된 응답으로 해석하는 최소 의미도 이번 설계에서 명시한다. 승인 의사와 실제 지급량은 분리한다. **제공 응답 후 자원 경합으로 0을 받음은 명시적 거절과 같지 않다.** 응답 원인 설명을 구현하지 않은 상태에서 원인을 창작하지 않는다.

## 6. 흔적은 ‘발견된 사실’이 아니다

M4의 `trace_created=true`는 물리적 흔적이 생겼다는 뜻이지, 경비·촌장·피해자가 이미 알아차렸다는 뜻이 아니다.

원시 M4 결과 로그를 나중에 게임 상태 대신 읽지 않도록 최소 `TraceState`를 저장한다. 최초 필드는 흔적 ID, 장소인 store ID, 발생 시점, 흔적 종류, 존재 상태와 내부 provenance로 제한한다. 사건의 실제 범인 ID를 미래의 조사자에게 공개하는 필드로 쓰지 않는다.

이번 M5는 흔적을 생성·보존할 뿐, A02 조사나 자동 재고 조사로 발견·범인 추론을 수행하지 않는다. 흔적이 있는 미목격 사건에서도 마을 평판은 그대로다. `TraceState`의 전체 직렬화와 후속 사용 전제는 상세 명세에서 고정한다.

## 7. 현재 믿음과 전달 기록을 분리한다

### 7.1 기존 구조의 제약

현재 Schema 4의 `InformationState`는 M3가 읽는 제한된 fact 종류만 허용하며, `(owner_person_id, fact_type_id, subject_id)`가 유일하다. 같은 사람·같은 fact에 상반된 전언 두 개를 단순 append할 수 없다.

따라서 `InformationState`를 무제한 소문 저장소로 바꾸지 않는다.

| 상태 | 역할 |
|---|---|
| `SocialObservationState` — 신규 제안 | 무엇을 직접 경험하거나 전해 들었는지, 출처·전달 깊이·수용 상태·최초 습득 시점 |
| 기존 `InformationState` | M3에 제공할 현재의 구조화된 주관적 믿음, 기존 유일키 유지 |
| 기존 `MemoryState` | 그 사람에게 남은 경험·해석·감정의 제한된 상세 기억 |
| 최소 사건별 적용 상태 | 같은 사건을 재청취·재처리해 관계·감정·압력을 중복 적용하지 않도록 저장 |

전언 전체 이력을 모든 NPC에게 복제하지 않는다. 실행에 필요한 현재 인식·최선 출처·중복 적용 상태만 보존하고, 상세한 전달 경로의 검증 기록은 별도 artifact로 둔다. 인물별 인식에는 최초 정보원, 직전 전달자, 전달 깊이, 출처 종류와 신뢰도를 유지한다.

### 7.2 충돌과 수용

같은 사실에 대한 여러 보고는 먼저 정렬·통합한 뒤 하나의 현재 믿음으로 반영한다. 정책은 다음을 만족해야 한다.

- 직접 경험, 전달자의 신뢰, 기존 믿음과의 충돌, 정보의 관측 시점을 구분한다.
- 습득한 날짜가 최신이라는 이유로 오래된 소문을 새 직접 관측보다 우선하지 않는다.
- 거부한 보고가 기존 믿음을 덮어쓰지 않는다.
- 같은 사건·같은 원천의 소문을 여러 번 들었다고 독립 증거처럼 확신을 더하지 않는다.
- 같은 사건에 대한 보고들의 기여를 모두 합산하지 않는다. 최초 버전은 최선 근거를 선택하는 보수적인 방식으로 제한한다.
- 동급의 상반된 근거는 기존 믿음을 유지하거나 미확정 상태로 남긴다. ID 순서로 어느 내용이 참인지 판정하지 않는다. ID는 같은 의미의 동률 기록 선택에만 사용한다.
- 충돌 판정·가중치·임계값은 결정 26에서 수치화하며, 객관적 사건의 ‘정답’을 조회해 진위를 해결하지 않는다.

허위 정보 생성 행동은 이번 범위가 아니지만, 잘못된 초기 믿음이나 서로 다른 해석은 허용한다. 오류가 있는 믿음도 인물이 실제로 가진 입력이라면 판단에 영향을 줄 수 있다.

### 7.3 판단용 믿음의 생성 경계

최초 학습 경로는 A04 요청자의 직접 경험에서 기존 `request_success_expectation`을 갱신하는 경우를 우선한다. 이는 그 사람이 이후 도움을 얼마나 기대하는지에 대한 자기 추정이다. 실제 지급 단위를 `0~100` belief 값에 그대로 대입하지 않는다. 정확한 학습률·정규화·confidence 규칙은 상세 명세에 둔다.

다른 사람이 도움받았다는 전언을 들었다고, 수신자 자신의 요청도 같은 확률로 성공한다고 복사하지 않는다. A11 실패만으로 창고가 비었다고 확정하거나, 절도를 봤다는 이유로 창고의 실제 보안·잔량을 알게 하지 않는다.

M3의 후보를 만들려면 기존 필수 fact가 모두 있어야 한다. 새 사건 하나가 없는 접근 권한·기회·권위자 정보를 임의로 채우지 않는다. 정보가 없어서 후보가 여전히 생성되지 않는 것은 허용된 결과다.

## 8. 사회적 접촉과 소문

접촉 자체는 명시적인 `SocialContactPlan`으로 받는다. 발행자는 해당 날짜의 유효한 사람·접촉 쌍을 보증하고, M5는 참조·날짜·중복·처리 상한을 검증한다. 관계가 좋다는 이유만으로 실제 접촉이 있었다고 생성하지 않는다.

최초 정책의 제안은 다음과 같다.

- 한 날짜에 사회적 접촉 pass는 한 번만 허용한다.
- pass 시작 시점의 인식·관계·감정 snapshot을 기준으로 모든 발신·수용을 계산한다.
- 그 pass 중 받은 새 전언이나 새 관계 변화는 같은 pass의 발신·수용 계산에 다시 사용하지 않는다.
- 따라서 A→B→C 접촉이 같은 pass에 있어도, B가 이번에 처음 들은 일을 그 자리에서 C에게 재전파하지 않는다.
- 사람당 하루 접촉 상대 최대 3명, 한 방향의 접촉당 주장 최대 2개를 최초 수치 후보로 둔다. 과다 접촉은 caller 입력 오류로 처리하며, 넘치는 주장 후보는 중요도·관련성·안정적 ID로 선택한다.
- 발신자는 실제로 보유하고 수용한 인식만 전달한다. 직접 경험 여부를 바꾸거나 내용을 무작위로 왜곡하지 않는다.
- `is_secret=true`인 내용은 일반 대화에서 제외한다. 비밀 누설·고발·의무 예외는 별도 행동으로 나중에 다룬다.
- 직접 목격·직접 상호작용·본인 경험·전언을 끝까지 구분한다. 전달받은 정보를 직접 목격으로 세탁하지 않는다.

최초 비밀 기본 정책은 A11 행위자의 자기 절도 경험을 비밀로 둔다. 일반 대화 pass가 그 경험을 자동 자백으로 유출하지 않는다. 별도 비밀 의무가 없는 목격자의 관찰은 전달 후보가 될 수 있다. A04의 일반 요청·응답은 기본적으로 전달 가능하지만 자동 공개는 아니다. 비밀 여부는 소유자별 인식에 속하며, ‘범죄 사건이므로 모든 목격 정보도 비밀’ 같은 전역 플래그로 처리하지 않는다.

관계·중요도·비밀·위험을 쓰는 발신 선택과, 수신자가 **전달자를** 신뢰하는 정도를 쓰는 수용 판단을 분리한다. 아직 없는 ‘사교성’ 같은 성격 축은 추가하지 않고, 필요한 공통 기본값은 규칙에 명시한다.

신뢰도는 다음 불변식을 갖는다.

```text
0 <= receiver_confidence <= sender_confidence <= 100
추가 전달은 신뢰도를 낮춤
수신자→전달자 신뢰가 높을수록 수용 가능성이 낮아지지는 않음
같은 원천 소문의 순환 전달은 확신과 관계 효과를 증폭하지 않음
```

최초 버전의 발신·수용·해석은 결정론적 규칙으로 제한한다. M4 목격 이후에 불필요한 추가 난수를 넣지 않는다. 정확한 신뢰도 감쇠식, 미관계 기본값, 수용 임계값, 중요도·관련성 계산은 결정 26의 동결 대상이다. 추가 전달의 감쇠는 0보다 큰 신뢰도에서 최소 1 이상 감소해야 한다.

## 9. 해석과 관계·감정 변화

해석기는 수신자의 현재 자기 성향·가치관·상태, 방향성 관계, 이미 가진 믿음과 허용된 인식 내용만 읽는다. 상대의 숨은 성향이나 outcome의 내부 응답 효용을 읽지 않는다.

| 경험 | 허용할 해석의 방향 | 금지할 지름길 |
|---|---|---|
| 직접 도움을 받음 | 감사, 신뢰·의무감 등의 변화 | 정확한 상대 재산이나 무조건적 선량함을 알아냄 |
| 직접 요청을 거절당함 | 다음 도움에 대한 기대 갱신, 자신의 절박함에 따른 실망·원망 | 거절이 언제나 악의라는 확정 |
| 제공 응답과 실제 지급량이 다름 | 약속된 응답과 체감 결과를 구분해서 기억 | 자원 경합을 무조건 배신으로 처리 |
| 절도를 직접 시도함 | 자기 규범 충돌, 죄책감 또는 자기합리화 압력 | 성공하면 자동으로 규범 점수 하락 |
| 절도 시도를 목격·믿음 | 자기 가치관과 이미 아는 맥락에 따른 대상 평가 | 몰랐던 가족 사정·의도를 시스템이 알려줌 |
| 전언을 들었지만 믿지 않음 | 전언 수신 및 미수용 기록 | 그 주장에 따른 대상 평판·관계·일반 성향 변화 |

이 표의 방향은 심리 모델의 제안이며 특정 선택을 강제하는 성공 oracle이 아니다. delta의 허용 대상, 양·음 방향, 조건, 크기, 기본값은 기계적으로 계산 가능한 표로 상세 명세에서 고정한다.

관계는 기존 다섯 축 `trust`, `affection`, `fear`, `resentment`, `obligation`과 `0~100` 범위를 유지한다. 모든 관계는 `A→B`다. `B→A`를 함께 갱신하지 않는다. 의미 있는 변화가 생긴 방향만 sparse relation을 생성하고 역참조를 함께 관리한다.

같은 pass의 변화를 입력 snapshot에서 전부 계산하고 `(owner, target, field)`별로 합산한 뒤 한 번 범위 제한한다. 순서대로 매번 clamp하여 배열 순서에 따라 값이 달라지는 처리를 금지한다.

### 사건별 적용 정책

동일 소유자·동일 사건에 대한 사회적 반응은 최초 수용 시 한 번만 적용한다. 처음에는 믿지 않았다가 나중에 수용하면 그때 한 번 적용한다. 같은 사건의 더 높은 신뢰도·다른 전달 경로는 인식의 출처를 개선할 수 있지만, 이미 적용한 관계·감정 효과 전체를 다시 더하지 않는다.

한 사건을 여러 주장으로 쪼개도 한 번의 반응 묶음으로 평가한다. 같은 pass에 들어온 보고를 먼저 결합하고, 그다음 수용·변화를 결정한다. 미래의 체계적인 허위 고발·철회·관계 복구 모델은 별도 확장이다. 현재 믿음이 수정됐다고 과거 관계값을 기계적으로 원복하지 않는다.

## 10. 기억을 다음 판단에 연결하는 방식

기존 M3는 `MemoryState`, `EventRecord`, 자연어 `claim`을 직접 읽지 않는다. 이 경계를 유지한다. M5는 경험에서 필요한 **현재 판단 상태**를 갱신하고, M3는 이를 읽는다.

| M5가 바꾸는 상태 | 현재 M3에서 영향을 받을 수 있는 경로 |
|---|---|
| `request_success_expectation` 등 허용된 주관적 fact | 후보 자격 또는 예상 이익 등 해당 fact의 기존 사용처 |
| 행위자→상대의 방향성 관계 | 관계 구성요소 R |
| `emotion_scores.fear` | 위험 비용 K |
| 주간 `norm_adherence` 변화 | 절도 규범 충돌 C |
| 주간 `risk_taking` 변화가 명세에 채택되는 경우 | 위험 비용 K |

`anger`·`guilt` 등의 감정과 기억은 의미 있게 기록할 수 있지만, 현재 M3가 그 값을 직접 점수화한다고 주장하지 않는다. 새 감정의 직접 효용 효과나 별도의 기억 가중치를 추가하려면 decision 규칙 버전의 명시적 변경이 필요하며, 이번 제안에서는 하지 않는다.

감사 artifact는 `경험 → 적용 규칙 → 실제 변경 필드 → 이후 후보 계산의 입력`을 추적할 수 있게 한다. 다음 판단이 원시 로그에서 과거 사건을 다시 계산하지 않는다. 기억 한 건을 읽을 때마다 관계 효과를 다시 받는 구조도 사용하지 않는다.

환류 시험에서는 자원·날짜·판단용 seed를 맞춘 대조 상태와 비교해, 변화가 식량 증감 때문인지 사회적 학습 때문인지 분리한다. 사회적 변경 필드가 계산에 반영됐다는 것과 최종 선택이 바뀌었다는 것을 별도로 보고한다.

## 11. 성향 변화 압력과 주간 정리

### 11.1 행동 직후

성향 자체의 즉시 큰 변화를 금지하고 signed pressure를 저장한다. 기존 결정 4의 속도를 유지한다.

| 경험 | 기존 승인된 원칙 |
|---|---|
| 사소한 행동 | 변화 없음 |
| 의미 있는 선택 | 압력 크기 1–3 |
| 큰 비용을 감수한 결정적 선택 | 압력 크기 4–8 |
| 주간 정리 | 성향별 최대 ±2 |

압력의 방향은 선택의 의미·규범 충돌·책임 인식으로 정하며, 절도 성공 여부만으로 정하지 않는다. 최초 유효 경로는 `norm_adherence`를 중심으로 좁힌다. 네 기존 성향 축 전체가 반드시 같은 시점에 변화할 필요는 없다.

자발성, 사전 위험 인식, 선택 당시 성향·가치관과 충돌, 직접 경험한 결과를 검증된 실행 시점의 자기 정보에서 추출한다. 필요한 최소 `ExperienceContext`는 M4 호출 전의 세계와 검증된 판단으로 내부에서 만든다. caller가 임의로 ‘큰 희생’·‘자발적’·‘두려움 없음’을 주입할 수 없게 한다.

현재 지원하는 자율 M3 선택은 자발적 선택으로 취급한다. 강제 행동·협박·충동 강제 실행이 추가되면 별도 provenance가 필요하다. 미래를 위해 지원하지 않는 강제성 enum만 만들어 완성된 것처럼 취급하지 않는다.

극단적 트라우마의 즉시 변화 예외는 기존 장기 원칙으로 남기되, 현재 세 행동만으로 근거 없이 발동하지 않는다. 타인의 소문을 들었다는 이유로 본인이 고위험 선택을 한 것과 같은 압력을 받지 않는다.

### 11.2 반복 감쇠와 주차

같은 저위험 행동의 반복 여부를 확인하는 최소 상태를 저장한다. 단순히 날짜나 action ID가 달라졌다고 새 경험의 전체 보상을 주지 않는다. 반복 key의 의미는 행위자·행동 계열·변화 대상 축을 중심으로 정의하고, 대상 인물만 바꿔 반복 감쇠를 우회할 수 있는지 시험한다.

주차별 정리는 한 번만 적용한다. 음·양 압력의 임계값 변환, 잔여 압력 이월, score `0/100` 경계 처리와 압력 누적 상한을 명시해야 한다. 적용하지 못한 변화량까지 잔여 압력에서 차감하지 않는다.

주간 한도는 동일 주차에 여러 번 호출했을 때도 성향별 ±2를 넘지 않아야 한다. 기억을 잊거나 압축했다고 반복 감쇠 상태·주간 사용량이 초기화되지 않는다.

## 12. 기억 단계와 압축

| 단계 | 제한 | 상태 |
|---|---|---|
| 최근 기억 | 최근 14일 | 기존 승인 원칙 |
| 중요 기억 | 최대 24개 | 기존 승인 상한 |
| 핵심 기억 | 최대 8개 | 기존 승인 상한 |
| 최근 기억 개수 | 최대 64개 제안 | 신규 수치 후보, 상세 명세에서 동결 |

한 기억은 한 단계에만 속한다. 제안된 개수 제한을 채택하면 상세 기억의 상한은 인물당 96개다. 일상적인 A00이나 반복된 소문만으로 중요·핵심 기억을 채우지 않는다.

발생일과 처음 알게 된 날을 구분한다. 어제 처음 들은 오래전 사건은 처음부터 오래된 수신 기억으로 취급하지 않는다. 반대로 같은 소문을 다시 듣는다고 최초 습득일을 오늘로 덮어써 최근 기억을 무한 연장하지 않는다.

단계 자격과 중요도 → 습득 시점 → 안정적인 ID의 정렬로 유지·강등·압축 대상을 결정한다. 중요·핵심 상한을 넘은 기억은 허용되는 하위 단계로 내리거나 요약한다. 배열 순서로 유지 대상을 결정하지 않는다.

**압축은 이미 적용한 관계·성향 효과를 보존하면서 상세 근거를 줄이는 작업이다. 추가 보상·벌점이 아니다.** 압축과 망각 때문에 관계·성향을 원복하지 않으며, 같은 효과를 다시 더하지도 않는다.

`MemoryState`가 새 사건 인식을 참조하려면 Schema 5에 source observation 참조를 추가한다. 새 기억이 M3용 `InformationState`를 억지로 만들어야만 저장되는 구조는 피한다. Schema 1–4의 기존 event/information 링크는 유지하고, Schema 5에서는 legacy 링크와 새 인식 링크의 허용 조합을 validator로 명확히 제한한다.

상세 인식을 압축할 때도 활성 믿음의 출처, 살아 있는 기억 링크, 중복 적용 방지에 필요한 최소 수신·적용 상태는 보존한다. 제거되는 ID를 참조하는 객체는 같은 원자적 작업 안에서 정리한다.

### 상세 기억 상한과 저장 크기는 별개다

상세 기억이 96개 이하라는 이유로 전체 저장 크기가 상수라고 주장하지 않는다. 객관적 사건·물리적 흔적·중복 방지용 최소 사건별 상태는 실제 사건 수에 따라 증가할 수 있다. 최초에는 이를 명시적 상태로 두고, 상세 보고 경로만 audit artifact로 분리한다.

M5 시험은 상세 기억 개수뿐 아니라 인식·적용 상태의 레코드 수와 저장 크기도 보고한다. 무제한 전체 전달 이력 복제나 전 인물×전 사건 복사는 금지한다. 안전한 제거·보존 기간을 정하지 못한 최소 중복 방지 상태를 조용히 삭제하지 않는다. 장기 보관 최적화는 관찰 결과를 근거로 별도 결정한다.

## 13. 하루 종료와 날짜 계약

M5는 독립적인 날짜 증가기를 만들지 않는다. 최초 test driver의 의미 순서는 다음과 같다.

1. 해당 날짜의 명시적 행동 batch를 M4+M5 통합 경로로 처리한다.
2. 명시적 접촉 목록으로 그 날짜의 사회적 pass를 한 번 처리한다. 대화가 없으면 빈 목록도 명시적으로 처리한다.
3. 하루 종료 wrapper가 기존 DayProcessor의 식량 소비·굶주림·건강 처리를 수행한다.
4. 완료한 날짜에 대한 M5 감정 정리·기억 유지·주간 압력 정리를 적용한다.
5. 전체 성공 시에만 다음 날짜의 세계를 반환한다. 다음 판단은 그 상태에서 새로 평가한다.

자원·건강 알고리즘과 날짜 증가의 책임은 기존 DayProcessor에 있다. M5의 정리 커널은 자원·건강·날짜를 변경하지 않는다. wrapper 안에서 DayProcessor가 `d→d+1`을 만든 뒤에도 정리 기준은 ‘완료한 날짜 d’로 명확히 전달하여 주차가 한 칸 밀리지 않게 한다.

첫 Schema 5 세계의 마지막 정리 날짜·주차 초기값, 주차 계산의 원점, 과거 날짜 중복 처리·날짜 건너뛰기 정책은 결정 26에서 exact 값으로 고정한다. 최초 버전은 하루씩 전진하며, 여러 날을 건너뛰어 중간 주간 정리를 생략하는 입력은 거부하는 쪽으로 제한한다.

이 wrapper는 호출된 한 번의 전이를 안전하게 처리하는 기능이다. 누구를 언제 행동시키고 누구와 만나게 할지 자동 결정하지 않는다. 따라서 M6의 scheduler를 선행 구현한 것으로 간주하지 않는다.

### 13.1 날짜 필드의 의미와 공통 경계 fixture — D26-R02

아래는 입력 세계의 `day_index=d`를 기준으로 한 대응표다. 기존 구현의 기록값과 M5 초안의 정리 기준을 구분하며, 주차 원점이나 14일의 포함·제외 조건을 새로 확정한 표는 아니다.

| 대상 | 날짜값 | 근거·상태 |
|---|---|---|
| M4 행동 context와 목격 seed | `d` | 현재 M4 구현 |
| M4 행동 자원 거래의 `day_index` | `d+1` | 현재 resolver의 `_build_transaction` |
| DayProcessor 소비 거래의 `day_index` | `d+1` | 현재 Schema 4 소비 계획 |
| DayProcessor가 반환하는 세계 | `d+1` | 기존 날짜 증가 책임 |
| M5 하루 종료 정리의 기준일 | 완료한 날짜 `d` | 이 초안 13절의 제안; wrapper가 명시적으로 전달 |
| 기억의 사건 발생일·최초 습득일 | 서로 구분하여 저장 | exact 필드와 나이 계산식은 결정 26에서 확정 |

자원 거래의 `d+1`을 사회적 사건 발생일·최초 습득일로 그대로 복사하지 않는다. 거래 기록일을 맞추려고 기존 M4·DayProcessor 날짜 의미를 변경하지도 않는다. 결정 26은 최초 날짜, 마지막 정리일·주차의 초기값, 주차 계산식과 발동일, 14일 기억 경계의 비교 연산자를 숫자와 식으로 고정해야 한다.

첫날부터 주차 경계와 14일 기억 경계까지 이어지는 **하나의 공통 연속 fixture**에서 행동일, 거래 기록일, 반환 세계 날짜, 정리 기준일, 주간 정리 여부, 최초 습득일과 기억 유지 여부를 같은 행에 기록한다. 늦게 들은 오래된 사건·반복 소문·저장 재개·중복 종료 호출도 이 날짜 기준을 공유해야 한다. 구체적인 날짜별 기대값과 fixture 원문은 결정 26의 미결 산출물이다.

## 14. Schema 5와 기존 코드 보존

단순히 `schema_version=5`를 붙이는 것으로는 현재 코드와 호환되지 않는다. 현재 `WorldState`, `StateCodec`, `StateValidator`, `StateHasher`, M3의 schema 분기와 `M4Rules`는 Schema 4의 필드·다섯 component manifest를 명시적으로 검사한다.

상세 설계는 다음 전략을 기준으로 작성한다.

- Schema 1–4의 기존 입력·직렬화·해시·fixture·실행 경로를 그대로 보존한다.
- Schema 5는 명시적인 opt-in 경로다. 기존 세이브를 몰래 승격하지 않는다.
- M5 전용 규칙은 최초에는 `social` component 하나로 묶고 그 내부에 관찰·전달·평가·기억·압력·정리 항목을 둔다.
- 기존 `resource`, `decision`, `parameterization`, `response`, `resolution`의 규칙 내용과 component hash는 보존한다. Schema 5의 simulation hash와 state hash는 새로 산출한다.
- 신규 schema를 지원하는 codec·validator·manifest 검증·service 진입 분기는 구현 승인을 받은 뒤 명시적으로 추가한다. 기존 M4 hash를 Schema 5 세계의 hash로 가장하지 않는다.
- M4의 exact artifact를 바꾸지 않는다. Schema 5에서의 새로운 실행 artifact는 별도 fixture로 계산하고 고정한다.
- `InformationState`의 현재 믿음과 `MemoryState`의 상세 경험, 압력·중복 방지 상태를 모두 저장·복원한다. 감사 로그가 없어도 미래 판단·반복 감쇠·정리 결과가 같아야 한다.

읽기 전용 조회에서도 소유자 경계를 적용한다. M3가 객관적 사건·흔적·다른 사람 인식 전체를 읽지 않는 구조를 유지한다. `player_person_id`를 바꾸더라도 같은 인물·같은 입력의 계산 의미가 달라져서는 안 된다.

이번 능력치·캐릭터 첨부 초안은 NON-CANONICAL 참고자료다. ‘능력과 성격의 분리’, ‘방향성 관계’, ‘주관적 Social Mind’ 원칙만 일치 여부를 확인했다. 첨부의 7개 능력치·추가 관계 축·15개 성격 축을 M5 정본으로 채택하지 않는다.

| M5-T20 | 상태 규모·공통 규칙 | 기억·인식·적용 상태 규모 보고, sparse 관계, 플레이어/NPC 동일 규칙 |

정보 경계 시험은 의미적 출력과 메타데이터를 구분한다. 비공개 사실이 바뀌면 전체 world hash는 바뀔 수 있지만, 그것을 모르는 사람의 인식 내용·후보·구성요소·선택은 같은 허용 입력과 seed에서 같아야 한다.

직접 인식 투영 시험과 해석기 시험을 분리한다. 허용된 관찰 payload를 고정한 해석기 시험에서는 차단된 입력을 바꿔도 결과가 달라지면 안 된다. M4의 실제 보안을 바꾸면 목격 seed 자체가 달라질 수 있으므로, 그 변화까지 모두 ‘정보 누출’이라고 판정하지 않는다.

## 16. 결정 26에서 닫을 상세 설계 항목

결정 25 v0.1의 범위·책임 검토 PASS를 바탕으로, 아래 항목을 한 세트로 작성·검산한다. 이 항목들이 남아 있는 동안 구현 착수 가능한 최종 명세라고 주장하지 않는다.

1. Schema 5 exact keyset, typed 모델별 소유권, ID·counter·역참조·legacy 링크 계약.
2. M4+M5 facade와 contact/close-day 진입점, trust boundary, 첫 실패 우선순위와 replay identity.
3. A04·A11 관찰 payload의 exact 허용 필드, 경험 시점 provenance, trace 상태.
4. 보고 충돌·출처 우선순위, 수용 임계값·confidence 감쇠·기본값·학습 정규화.
5. 관계·감정·중요도·해석·성향 압력의 조건별 수치표와 정수 반올림 규칙.
6. 반복 감쇠 key·기간·계수, 주차 원점·압력 임계값·이월·0/100 경계 정책.
7. 감정의 일일 정리, 기억 단계 자격·정렬·상한·압축, 최소 적용 상태의 보존 정책.
8. 신규 social ruleset exact JSON 및 hash, Schema 5 서비스별 authority와 호환 fixture.
9. 정상·경계·실패·저장 재개 fixture, 원시 M4 artifact 유지 검증, 손계산 가능한 수치 oracle.

사용자가 전달한 검토의 비차단 사항 두 가지를 다음과 같이 추적한다. ‘수용’은 상세 명세가 닫혔다는 뜻이 아니다.

| ID | 필수 확정 항목 | 상세화 위치 | 연결할 검증 | 상태 |
|---|---|---|---|---|
| D26-R01 | 내부 중간 세계와 최종 공개·저장 세계의 검증·해시 경계 | 4.4절, 위 1·2·8·9항 | M5-T01·T17·T18 | 수용 / 상세 미확정 |

## 17. 현재 검토 결과와 다음 게이트

사용자가 제공한 v0.1 범위·책임 검토 결과는 PASS이며 blocker는 없다. 주간 성향 정리와 기억 압축은 기존 승인된 M5 범위라는 판단을 수용한다. 두 비차단 사항은 4.4·13.1·16절에 결정 26의 필수 확정 항목으로 반영했다.

이번 개정에서는 해당 코드 구간을 동결 tree와 일치하는 로컬 작업 트리에서 읽기 전용으로 대조하고 문서를 점검했다. 구현 시험·Linux/Windows 실행·독립 레드팀 검증을 새로 수행한 것은 아니다. v0.2의 추가 내용에 별도의 검토 PASS를 부여하지 않는다.

확인하여 설계에 반영한 주요 위험은 다음과 같다.

- M4 내부 계산을 NPC가 아는 정보로 오인하는 문제.
- 목격 seed를 다시 지각 판정하거나 정밀한 재고 지식으로 확대하는 문제.
- A04의 자원 경합을 상대의 거절로 잘못 해석하는 문제.
- 전언 기록을 기존 InformationState에 중복 append해 유일키 계약을 깨는 문제.
- MemoryState가 현재 information 링크를 필수로 요구하여 순수 사건 기억을 표현하지 못하는 문제.
- 같은 사건 재청취·압축·주간 정리 반복으로 변화를 중복 적용하는 문제.
- 기억은 쌓였지만 M3의 계산 입력에는 아무 영향이 없는 문제.
- Schema 5와 새 manifest를 기존 service가 자동 지원한다고 가정하는 문제.

```text
M5 DESIGN WORK = AUTHORIZED / IN PROGRESS
DECISION 25 v0.1 SCOPE / RESPONSIBILITY REVIEW = PASS
DECISION 25 BLOCKER = NONE (제공된 범위 검토 기준)
DECISION 25 PROPOSAL = APPROVAL RECOMMENDED / NON-CANONICAL
DECISION 25 v0.2 = REVIEW COMMENTS INCORPORATED / NOT INDEPENDENTLY REVIEWED
DECISION 26 EXACT SPEC = PENDING
M5 IMPLEMENTATION = NOT AUTHORIZED
M4 BASELINE = UNCHANGED
```

다음 설계 작업은 **결정 26의 상세 명세와 검증 벡터 작성**이다. 기존 M5 설계 작업 승인은 유효하다. 결정 25의 정본 승인·저장소 반영과 M5 구현 승인은 아직 부여되지 않았다. 이번 개정은 범위 검토를 HOLD로 되돌리지 않으며, 미확정 세부 사항을 승인된 계약으로 취급하지 않는다.
