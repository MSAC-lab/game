# M6-0 최소 자동 진행·관찰 계약 v0.2

## 1. 승인과 기준선

```text
STATUS = CANONICAL / USER APPROVED
CONTRACT = M6-0 v0.2 + CONTACT WORDING CLARIFICATION
DESIGN AUTHORIZATION = GRANTED
B SCOPE AND RESPONSIBILITY REVIEW = PASS
B DESIGN SUPPLEMENTS REVIEW = PASS
PREVIOUS TWO SUPPLEMENTS = CLOSED
BLOCKER = NONE
IMPLEMENTATION AUTHORIZATION = NOT GRANTED
IMPLEMENTATION STATUS = NOT STARTED
M5 = MERGED / VERIFIED
BASELINE MAIN = 6d4aa8ad607b42c1ee6472c1b72b9d85b90ce369
BASELINE TREE = 9ef2415eb25eef9a5b6d5b0b7d17fbd3fe1dd6e1
```

사용자는 B의 v0.1 범위·책임 검토 PASS, v0.2 보완안 PASS와 접촉 문장 정정을 확인한 뒤 “설계 정본 승인한다.”라고 승인했다. 이 문서는 승인된 v0.1 본문, v0.2의 두 보완 사항과 마지막 접촉 문장 정정을 통합한 정본이다. 채팅 원문을 바이트 단위로 복제한 파일은 아니다.

설계 정본 승인은 구현·시험 PASS·PR 병합 승인을 뜻하지 않는다. 아래 API 이름과 반환 구조는 구현할 계약이며 기준 커밋에 이미 존재하는 기능으로 해석하지 않는다.

M5 기준선은 [PR #14](https://github.com/MSAC-lab/game/pull/14)의 병합 결과다. B의 병합 후 검증은 PASS이며 [병합 후 CI](https://github.com/MSAC-lab/game/actions/runs/33958806277)도 성공했다. 본 문서 채택으로 M5의 규칙·동결 자료·실행 결과를 변경하지 않는다.

## 2. 목적과 범위

목적은 기존 인과 루프를 사람이 매번 호출하지 않아도 여러 날 실행하고, 왜 그런 결과가 나왔는지 관찰하는 것이다.

기존 소규모 시험 환경과 구현된 행동 `A00·A04·A11`부터 연결한다. 새 행동·성향·경제 규칙은 추가하지 않는다.

[기존 M6 로드맵](https://github.com/MSAC-lab/game/blob/6d4aa8ad607b42c1ee6472c1b72b9d85b90ce369/docs/drought-prototype-v0.md#L1971-L1993)은 15가구·60명, 배경 인물 활성화, 행동군 완성, 30일 실행까지 포함한다. M6-0은 그보다 작은 최소 자동 진행·관찰 선행 단계다. M6-0 완료를 기존 M6 전체 완료로 처리하지 않는다.

최초 관찰은 현재 규칙으로 가능한 식량 압박 실험이다. 강수·수확·가격까지 구현된 가뭄으로 부르지 않는다. 반복 실행에서 확인한 현상과 원인을 바탕으로 다음 기능을 하나씩 제안한다.

첨부된 프로젝트 동기·역사 세계관·초기 인물 조사·캐릭터 모델 문서는 사용자 방향성 참고자료다. 이번 승인으로 그 자료들이 설계 정본이나 구현 규칙으로 승격되지 않는다.

## 3. 하루 실행 순서

하루는 다음 순서로 진행한다.

1. **판단:** 명시된 자동 판단 대상 중 생존자를 선정한다. 모두 동일한 하루 시작 상태를 기준으로 `daily_food_strategy`를 한 번씩 평가한다.
2. **행동:** 판단 결과를 하나의 묶음으로 M5 실행 경로에 제출한다.
3. **접촉:** 행동 반영 후 상태에서 그날의 접촉을 한 차례 처리한다.
4. **하루 마감:** 기존 식량 소비·굶주림·건강·기억 정리를 적용하고 다음 날로 넘어간다.

각 단계는 직전 결과의 상태·해시·revision으로 새 요청 stamp를 만든다. 같은 접촉 단계에서 막 전달받은 정보를 다시 연쇄 전달하지 않는다.

요청 거절·절도 실패 같은 정상적인 행동 결과 때문에 재추첨하거나 같은 날 다시 판단시키지 않는다. 행동하지 않는 부양가족도 기존 생활 규칙의 적용 대상이다.

### 3.1 자동 판단 대상이 없는 날

최종 승인 문장은 다음과 같다.

> 자동 판단 대상이 없으면 행동 실행 단계만 생략한다. 설정에 유효한 접촉쌍이 있으면 접촉을 처리하며, 접촉쌍도 없을 때에만 빈 접촉 계획을 처리한다. 접촉 처리에 성공하면 하루 마감으로 진행한다.

빈 행동 묶음은 제출하지 않는다. 자동 판단 대상 유무로 접촉 여부를 결정하지 않는다.

### 3.2 실행 결과와 중단의 구분

M5 호출 결과에 따른 중단 기준은 `ok=false`다. `ok=true`인 묶음 안의 개별 `INVALIDATED`나 정상적인 행동 실패는 기록하고 다음 단계로 진행한다.

진행기 자체의 진입 조건 또는 증거 검증 실패는 별도의 M6 오류로 처리하며, 개별 행동 실패와 혼동하지 않는다.

## 4. 하루 시작·재개 조건

기존 Schema 5 검증을 먼저 통과해야 하며, 현재 날짜를 `d`라 할 때 다음 조건을 모두 요구한다.

| 검사 필드 | 허용 조건 |
|---|---|
| `day_phase` | `DAY_END` |
| `social_state.last_closed_day_index` | `d - 1` |
| `social_state.last_contact_day_index` | `d - 1` |
| `resolved_decision_slot_ids` | 빈 배열 |
| `social_state.last_integrated_resolution_epoch` | `resolution_epoch`와 일치 |

`DAY_END`라는 이름만으로 하루 경계를 판정하지 않는다. 기존 M5는 당일 행동이나 접촉까지 처리한 상태도 유효한 세계로 인정한다. 진행기는 이러한 당일 중간 상태를 하루 시작 상태로 받지 않는다.

진입 경로는 다음과 같이 구분한다.

- **신규 실행:** 선언된 초기 fixture의 상태 해시와 일치하는 세계만 받는다.
- **재개:** 완료된 하루 경계에서 저장한 M6-0 체크포인트만 받는다. 세계 해시, 실행 설정 본문에서 재계산한 해시, 저장된 설정 해시, 진행기 버전과 규칙 식별자가 일치해야 한다.
- **조건 불일치:** 진입을 거부한다. 날짜·revision·slot을 초기화해서 맞추지 않는다.

당일 접촉을 이미 처리했다면 접촉쌍이 비어 있었더라도 하루 시작 상태로 다시 받지 않는다.

## 5. 현장과 접촉의 근거

최소 실행 환경은 다음과 같이 구성한다.

- 초기 실행 설정에 인물·창고의 고정 현장과 일일 접촉쌍을 명시한다.
- 실행용 현장 공급자가 이 설정과 현재 세계를 확인해 현장 문맥을 생성한다.
- 행동 대상으로 선택됐다는 이유로 상대나 창고를 현장에 끼워 넣지 않는다.
- 접촉쌍은 같은 현장의 생존자만 허용하며, 기존 1인당 하루 최대 3명 제한을 지킨다.
- 이동·근무 일정·동적 만남 선택은 이번 범위에서 제외한다.

이는 고정된 작은 실험 환경이다. 마을의 공간·이동 시스템을 완성했다고 해석하지 않는다. 테스트용 현장 공급자를 실행용 권한으로 취급하지 않는다.

## 6. 하루 단위 확정과 재현성

실행 결과를 좌우하는 초기 세계, 시드, 자동 판단 대상, 현장·접촉 설정, 진행기 버전을 함께 기록한다. 설정도 해시로 묶어 같은 세계에 다른 실행 설정을 붙인 경우를 구분한다.

세계 갱신은 하루 단위로 확정한다.

- 각 단계는 임시 상태에서 실행한다.
- 하루 마감까지 성공해야 그날을 확정한다.
- 중간 단계가 거부되면 마지막으로 완료한 날의 상태를 보존하고 중단한다.
- 실패한 날의 중간 기록은 진단용으로 남기되 확정된 세계 이력과 구분한다.
- 저장·재개는 완료된 하루 경계에서만 지원한다.

현재는 건강이 0에 도달하는 날을 사망 처리 미구현으로 거부한다. 이 경계에서는 중단하며, 건강 보정·소비 생략·식량 추가로 계속 돌리지 않는다.

진행기는 실패 단계와 M5 원진단을 보존한다. 일반 불변식 오류를 임의로 사망으로 재분류하지 않는다. 예상된 중단을 검증하는 시험의 PASS와 요청 기간 완주는 별개다.

## 7. 실제 행동 결과 원문 전달

### 7.1 관찰용 실행 경로

M5 내부 결과를 전달하는 관찰용 진입점을 추가한다.

```text
execute_decisions_observed_v1(...)
  → operation_result: 기존 M5OperationResult
  → m4_batch_artifact: 실제 실행 결과 스냅샷 또는 null
```

관찰용 진입점도 기존 내부 실행 경로를 한 번만 실행한다. 내부의 M4 묶음 검증을 통과한 직후, M5 사회적 반영을 시작하기 전에 원문을 확보한다. 사건 기록에서 복원하거나 같은 행동을 재실행해 얻지 않는다.

### 7.2 원문의 범위

원문은 다음 두 요소로 구성한다.

- 기존 `to_data_without_batch_artifact_hash_and_next_world()`의 본문 전체.
- 그 묶음의 기존 `batch_artifact_hash`.

이 본문에는 `A00·INVALIDATED`를 포함한 전체 행동 결과, 무효화 사유, 거래, 목격 증거와 거부 진단이 들어 있다. 실행 중간의 `next_world` 객체는 관찰 결과에 포함하지 않는다. 기존 M4 해시도 해당 객체를 제외한 본문에 결속돼 있다.

### 7.3 호환과 결속

- 기존 `execute_decisions_v1`과 `M5OperationResult.to_data()`의 반환 구조를 유지한다.
- 동일 입력에서 기존 경로와 관찰용 경로의 `operation_result`는 정규 직렬화 결과까지 같아야 한다.
- 확보한 원문은 실행 객체와 참조를 공유하지 않는 스냅샷으로 보관한다.
- 원문 해시를 재계산하고 M5 artifact의 `m4_batch_artifact_hash`와 대조한다.
- 관찰 원문은 개발자 기록으로만 사용하며 NPC 인식에 직접 넣지 않는다.

### 7.4 원문 유무와 확정 여부

| 상황 | 관찰 기록 |
|---|---|
| 판단 대상이 없어 행동 단계를 생략 | 호출 생략 표시, 원문 `null` |
| M4 실행 전 거부 또는 묶음 검증 실패 | 검증된 원문 없음 표시, 원진단 보존 |
| 검증된 M4 `REJECTED` 반환 | 실제 거부 원문 보존, M5 실패에 따라 중단 |
| M4 성공 후 M5 또는 하루 마감 실패 | 확보한 원문 보존, 해당 날은 미확정 |

마지막 경우에도 원문의 `COMMITTED`를 고쳐 쓰지 않는다. M4 묶음의 성공과 하루 전체 확정 여부를 별도 필드로 기록한다.

원문 누락·해시 불일치는 M5 결과를 변조하지 않고 별도의 M6 증거 검증 오류로 처리해 그날을 확정하지 않는다.

## 8. 관찰 기록과 합격 기준

실행마다 완료 일수, 일별 상태 해시, 인물별 판단 기록, 행동 결과, 정보·기억·관계 변화, 자원 거래 및 중단 사유를 연결해 남긴다.

합격 기준은 다음과 같다.

- 같은 초기 상태·시드·설정에서 동일한 결과가 나온다.
- 동일한 입력으로 기존 공개 실행 경로를 수동 호출한 결과와 일치한다.
- 입력 배열 순서 변경과 하루 경계 저장·재개가 결과를 바꾸지 않는다.
- 현장 밖 목격, 접촉 없는 전언, 숨은 정보의 판단 유입이 발생하지 않는다.
- 실패한 날의 부분 상태가 확정되지 않는다.
- 기존 M0–M5 회귀 검사와 Linux·Windows 재현성을 유지한다.

두 설계 보완에 대응하는 검증 항목은 중간 상태 재개 거부, 설정 불일치 거부, A00·INVALIDATED 원문 보존, 단일 실행, 두 반환 경로의 동일성, 마감 실패 시 하루 미확정이다.

절도가 반드시 발생하거나 특정 이야기가 나오는 것은 합격 조건이 아니다. 여기의 합격 기준은 앞으로 구현을 검증할 계약이며 M6-0 시험을 이미 실행하거나 통과했다는 보고가 아니다.

## 9. 승인 범위와 후속 단계

B의 v0.1 범위·책임 검토와 v0.2 보완안 검토는 PASS다. 하루 시작·재개 조건과 실제 행동 결과 원문 전달이라는 기존 두 보완 사항은 설계 계약상 CLOSED다. 마지막 비차단 표현 보완은 3.1절의 접촉 문장으로 반영했다.

이번 사용자 승인 범위는 이 설계 정본이다. M6-0 실행 코드, 관찰용 M5 진입점, 신규 시험과 실행 데이터의 구현 착수 권한은 아직 부여되지 않았다.
