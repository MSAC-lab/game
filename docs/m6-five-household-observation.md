# M6 5가구 관찰 실행

승인된 [5가구 초기 설정·비교안](proposals/m6-five-household-observation-v0.1.md)을 현행 M0–M6-0 규칙으로 실행한다. M7 진입이나 새 성격·처벌·배급 규칙의 구현이 아니다.

- 설계 병합: `478db4a3498a96d1a2ce3a5318c11d312afbc0e3` (PR #17).
- 초기 세계: [m6-five-household-observation-v1.json](../scenarios/m6-five-household-observation-v1.json).
- 실행·집계: [observe_five_households.py](../tools/observe_five_households.py).
- 기존 4명 시나리오·규칙·엔진·동결 자료·CI 설정은 그대로 둔다.

## 실행 방법

Godot 4.7.2 Standard와 Python 3을 사용한다. 저장소 루트에서 실행한다.

```sh
godot --headless --editor --path . --quit
python tools/observe_five_households.py --godot godot --output-dir builds/five-household
```

실제 실행은 기존 `tools/run_m60.gd` → `M60Runner.run_v1`을 사용한다. Python은 입력 변형, 프로세스 호출, 이미 반환된 기록의 집계만 담당한다. 판단·응답·원장·사회적 효과를 재구현하거나 실행 결과를 바꾸지 않는다.

F00은 28일을 요청한다. C01–C08은 F00에서 원인 입력 하나와 파생 초기 해시만 바꾸고 각각 첫날을 실행한다. F00 반복 실행, 7일 체크포인트와 추가 21일 실행도 대조한다. 각 파일의 라벨은 외부 식별자이며 세계의 scenario ID·seed·개체 ID를 바꾸지 않는다. 입력 해시 계산은 기존 정렬 규칙을 따르며, 각 입력을 네이티브 로더가 다시 검증한다.

`--mode remaining`은 이미 생성된 F00 원문·체크포인트의 초기 입력 결속을 확인한 뒤 나머지를 실행한다. 현재 최초 F00은 같은 CLI를 직접 호출해 만들었고, 그 결과를 재사용했다. `--mode collect`는 존재하는 전체 원문을 집계하며 네이티브 실행을 다시 하지 않는다. 필수 원문이 없거나 입력·체크포인트가 맞지 않으면 실패한다.

## 이번 기준 실행에서 발생한 일

**28일을 완주했지만 주민 모두가 굶주린 상태로 끝났다.** 기간 완주는 마을 생존 전략의 성공을 뜻하지 않는다. 15명은 모두 생존 상태이며 마지막 건강은 10–60, 굶주림은 전원 100이다. 이번 F00에서는 건강 경계 중단 경로가 실행되지 않았다.

| 시점 | 실제 진행 |
|---|---|
| 1일 | 부족한 가구의 5명이 도윤(P04)에게 요청해 각 10, 합계 50을 받았다. |
| 2일 | 5명의 요청에 총 34가 지급됐다. 각 응답은 전액 제공을 허용했지만 같은 창고의 자원 경합으로 실제 지급은 6–7이었다. |
| 3일 | 도윤 가구의 3명이 서준(P07)에게 각 6, 합계 18을 받았다. |
| 4일 이후 | 모든 요청의 실제 획득량이 0이었다. |
| 7일 | 길상 가구(H05)의 식량이 먼저 0이 됐다. |
| 16일 | 모든 가구 창고의 식량이 0이 됐다. |
| 28일 | 공동창고 식량 120은 그대로 남았고, 주민들은 요청을 반복했다. |

28일의 자동 판단 252건은 **요청 A04 231건, 대기 A00 21건, 절도 A11 0건**이다. A04의 결과는 전량 획득 8건, 일부 획득 5건, 무획득 218건이다. 누적 가구 간 이동량은 102이며 식량 생성량이 아니다. 실제 소비 278과 마지막 잔량 120의 합이 최초 398과 일치한다. 각 저장소의 유입·유출·소비·잔량도 원장과 대조한다.

10일치 보호 기준은 마감 잔량 보장이 아니다. 예를 들어 2일 시작 도윤 가구의 94에서 구호로 34를 주면 60이지만, 이후 일일 소비 6을 처리해 마감 잔량은 54다.

## 왜 실패한 요청을 반복했는가

한결(P01)의 도윤에 대한 요청 성공 기대는 첫 성공 뒤 **80→85**, 반복 무획득을 거쳐 **2**까지 내려갔다. 학습 경로는 동작했다. 그러나 28일의 판단 점수는 **요청 6,245, 공동창고 절도 5,010, 대기 0**이어서 요청이 계속 우세했다.

이는 기록과 현행 식을 대조한 원인 해석이다. 요청의 낮은 기대 이익은 M 항목을 낮추지만, 목표 기여 G=100과 가치·관계 점수가 계속 더해진다. 굶주림에 따른 N 증가는 요청과 절도 양쪽에 들어가며, 절도에는 규범 갈등 비용도 있다. 따라서 이번 입력에서는 기대가 낮아져도 요청 우위가 뒤집히지 않았다. 정수 반올림 때문에 반복된 0 표본에서도 기대가 2에 머무는 현상도 관찰됐다.

공동창고의 식량은 자동 배급되지 않는다. 이번 시나리오에서 그것을 옮길 수 있는 기존 절도 행동도 선택되지 않아 120이 남았다. A11 재고 믿음의 경험 갱신, 절도의 직접 목격·흔적·규범 압력, 처벌 효과는 이번 실행으로 검증했다고 주장하지 않는다.

## 검증과 범위

Linux / Godot 4.7.2에서 아래 검증을 완료했다. [집계 JSON](evidence/m6-five-household-v1/summary.json)과 [전체 네이티브 기록·체크포인트 묶음](evidence/m6-five-household-v1/native-records.tar.gz)을 보존한다. 원문에는 판단 후보·제외 사유·추첨 근거·입력 출처와 실제 M4 묶음·응답 평가·원장·M5 반영·체크포인트가 포함된다. 집계 결과는 그 원문에서만 계산한다.

```text
LOCAL EXECUTION = F00 28/28 COMPLETED; C01-C08 1/1 COMPLETED
COMPARISON PATHS = 8 PASS / 0 NOT_EXERCISED
REPEAT FULL RECORD BYTES = IDENTICAL
7+21 RESUME = SAME DAY RECORDS / FINAL WORLD / CHECKPOINT BYTES
FOOD CONSERVATION = PASS (398 = 278 CONSUMED + 120 REMAINING)
HEALTH BOUNDARY / THEFT EXECUTION = NOT EXERCISED
IMPLEMENTATION REVIEW = B REVIEW PENDING
IMPLEMENTATION PR MERGE = SEPARATE
```

저장된 원문만 다시 집계하려면 묶음의 파일들을 빈 작업 디렉터리에 풀고 `python tools/observe_five_households.py --mode collect --output-dir <그 디렉터리>`를 실행한다. 각 파일의 SHA-256과 크기는 집계 JSON의 `native_files`에 있다. 연속 28일과 저장 재개의 `requested_days`·`advanced_days` 호출 메타데이터는 다르므로 그 두 필드를 제외한 전체 결과와 체크포인트 바이트를 대조한다. 새 5가구 시험의 Windows 실행 결과는 이 로컬 기록에 포함하지 않는다.

이번 결과로 다음에 검토할 후보는 **획득 기대가 낮아진 행동의 목표 기여를 판단에 어떻게 반영할지**다. 성격 항목을 더 늘리기 전에, 이 반복 요청을 하나의 구체적 사례로 삼아 규칙 변경 하나를 설계·대조할 수 있다. 아직 해당 변경이나 공동창고 배급·절도 처벌을 구현하지 않았다.
